# ความปลอดภัย

## สิ่งที่ระบบนี้ป้องกัน และไม่ป้องกัน

**ป้องกัน:** การเรียกใช้ GPU sidecar โดยไม่ได้รับอนุญาตจากคนอื่นในเครือข่าย
เดียวกัน และการที่เสียงพูดของคุณถูกส่งไปยังผู้ให้บริการภายนอก

**ไม่ป้องกัน:** ผู้ที่เข้าถึง tailnet ของคุณได้แล้ว, ผู้ที่อ่านไฟล์ `.env`
บนเครื่องได้, และการดักฟังระหว่าง sidecar (ดู [TLS](#tls-ระหว่าง-host-กับ-node))

## Token

sidecar ทั้งสองใช้ shared secret ผ่าน header `X-Jarvis-Token`

```bash
openssl rand -hex 32
```

| กฎ | เหตุผล |
|---|---|
| STT กับ TTS ใช้คนละ token | เพิกถอนทีละส่วนได้เมื่อตัวใดตัวหนึ่งหลุด |
| เก็บใน `.env` เท่านั้น ไม่ใส่ใน YAML | `server.yaml` ถูก commit ได้ `.env` ไม่ถูก |
| `chmod 600 .env` | ค่าเริ่มต้นของ umask หลายเครื่องยังให้ group อ่านได้ |
| หมุน token เมื่อมีคนออกจากทีม หรือเมื่อหลุดเข้า log/แชท | token ที่เคยปรากฏใน transcript ต้องถือว่าหลุดแล้ว |

**ถ้าไม่ตั้ง token เลย sidecar จะรับทุก request** — โค้ดตั้งใจให้เป็นแบบนี้
เพื่อความสะดวกตอน dev บน localhost แต่ห้ามใช้แบบนี้บนเครื่องที่ผูกกับ
tailnet หรือ LAN

## การเปิดพอร์ต

ค่าเริ่มต้นใน `.env.example` คือ `0.0.0.0` ซึ่งเปิดทุก interface บนเครื่องที่
อยู่บน Tailscale อย่างเดียวก็พอรับได้ แต่ถ้า node นั้นอยู่บน LAN ที่มีคนอื่นด้วย
ให้ผูกกับ tailnet address โดยตรง:

```bash
JARVIS_STT_HOST=100.84.136.110
JARVIS_TTS_HOST=100.84.136.110
```

หรือกันด้วย firewall:

```bash
sudo ufw allow in on tailscale0 to any port 8768,8769,8767 proto tcp
sudo ufw deny 8768,8769,8767/tcp
```

## TLS ระหว่าง host กับ node

ปัจจุบันการคุยกันระหว่าง host กับ sidecar เป็น **HTTP ธรรมดา** ซึ่งยอมรับได้
เมื่ออยู่บน Tailscale เพราะ WireGuard เข้ารหัสให้อยู่แล้วในระดับ transport

**แต่ถ้าจะรันข้ามเครือข่ายที่ไม่ใช่ tailnet ต้องเพิ่ม TLS เอง** — ทางที่ง่าย
ที่สุดคือวาง reverse proxy (Caddy/nginx) หน้า sidecar แล้วให้ host เรียกผ่าน
`https://`

## ข้อมูลอะไรไปไหนบ้าง

| ข้อมูล | ปลายทาง | ออกนอก tailnet ไหม |
|---|---|---|
| เสียงพูดดิบ | GPU node เท่านั้น | ไม่ |
| ข้อความที่ถอดได้ | Hermes Agent → LLM provider | **ใช่** — ไปที่ LLM gateway |
| เสียงที่สังเคราะห์ | host → เบราว์เซอร์ | ไม่ |
| คลิปเสียงอ้างอิง | อยู่บน GPU node | ไม่ |

จุดที่ข้อมูลออกนอกคือ **LLM เท่านั้น** ถ้าต้องการปิดสนิท ต้องชี้ Hermes ไป
ที่โมเดลที่รันเองในเครือข่าย

## Prompt injection ผ่านเสียง

ผู้ช่วยเสียงที่ต่อกับ agent ที่รันคำสั่งได้ มีความเสี่ยงเฉพาะตัว: ใครก็ตาม
ที่พูดใส่ไมค์ได้ ก็สั่ง agent ได้ ทุกอย่างที่ได้ยินคือ input ที่ไม่น่าเชื่อถือ

มาตรการที่มี:

- **`hermes.instructions` สั่งห้ามพูดความลับออกเสียง** — บรรเทา ไม่ใช่การป้องกัน
- **upstream มี approval cards** สำหรับคำสั่งอันตราย — ควรเปิดใช้
- **privacy filter ของ upstream** กรองสตริงที่มีรูปแบบเหมือน secret ก่อนส่งไป TTS

ข้อแนะนำ: อย่าให้ agent ที่ต่อกับเสียงมีสิทธิ์มากเกินจำเป็น และเปิด approval
สำหรับคำสั่งที่แก้ไขระบบเสมอ
