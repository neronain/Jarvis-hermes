# เสียงพูดภาษาไทย (F5-TTS-TH)

## โมเดลนี้ทำงานยังไง

F5-TTS เป็นโมเดล **zero-shot voice cloning** ที่ใช้เทคนิค flow matching —
ไม่ได้ถูกเทรนให้มี "เสียง" ตายตัว แต่รับคลิปเสียงอ้างอิงสั้น ๆ พร้อม
ข้อความถอดเสียงของคลิปนั้น แล้วสังเคราะห์ข้อความใหม่ด้วยน้ำเสียงเดียวกัน

ผลที่ตามมาซึ่งสำคัญต่อการใช้งาน:

- **เปลี่ยนเสียง = เปลี่ยนไฟล์ config** ไม่ต้องเทรนใหม่ ไม่ต้องโหลดโมเดลใหม่
- **คุณภาพขึ้นกับคลิปอ้างอิงเป็นหลัก** โมเดลดีแค่ไหนก็ชดเชยคลิปแย่ ๆ ไม่ได้
- **ข้อความอ้างอิงต้องตรงกับเสียงเป๊ะ** นี่คือสาเหตุอันดับหนึ่งของเสียงเพี้ยน

แพ็กเกจที่ใช้คือ [`f5-tts-th`](https://pypi.org/project/f5-tts-th/) (v1.0.9)
ซึ่งห่อโมเดลไทยจาก [`VIZINTZOR/F5-TTS-TH-V2`](https://huggingface.co/VIZINTZOR/F5-TTS-TH-V2)

## เลือก v1 หรือ v2

| | `v1` | `v2` |
|---|---|---|
| การออกเสียงไทยโดยรวม | เป็นธรรมชาติกว่า | แข็งกว่าเล็กน้อย |
| คำพ้องรูป / คำทับศัพท์ | อ่านผิดบ่อยกว่า | ใช้ IPA ช่วย จึงผิดน้อยกว่า |
| เหมาะกับ | บทสนทนาทั่วไป | ข้อความที่มีศัพท์เทคนิค/ชื่อเฉพาะ |

ค่าเริ่มต้นของโปรเจกต์นี้คือ **`v2`** (`JARVIS_TTS_MODEL=v2`) เพราะผู้ช่วย
ต้องอ่านชื่อไฟล์ คำสั่ง และศัพท์เทคนิคบ่อย ถ้าใช้คุยเล่นเป็นหลัก ลอง `v1` ดู

## การเตรียมเสียงอ้างอิง

### ข้อกำหนดของคลิป

| ข้อ | เหตุผล |
|---|---|
| ยาว 5–15 วินาที | สั้นกว่านี้จับ timbre ไม่พอ ยาวกว่านี้ไม่ได้อะไรเพิ่มแต่ทำให้ทุก request ช้าลง |
| ผู้พูดคนเดียว ไม่มีเสียงรบกวน | โมเดลลอกทุกอย่างที่ได้ยิน รวมทั้งเสียงรบกวน |
| ไม่มีดนตรี เสียงก้อง หรือ artifact จากการบีบอัด | สิ่งเหล่านี้จะกลายเป็นคุณสมบัติถาวรของเสียง |
| พูดด้วยจังหวะและระดับเสียงปกติ | คลิปคือ baseline ส่วน `speed:` แค่ปรับเล็กน้อย |
| WAV mono 24 kHz | เป็น native rate อย่างอื่นถูก resample ตอนโหลด |

### แปลงไฟล์

```bash
ffmpeg -i input.m4a -ac 1 -ar 24000 -sample_fmt s16 voices/jarvis_ref.wav
```

ถ้าคลิปมีเสียงรบกวน ตัดออกก่อนดีกว่าปล่อยให้โมเดลลอกไป:

```bash
ffmpeg -i noisy.wav -af "highpass=f=80,afftdn=nf=-25" -ac 1 -ar 24000 clean.wav
```

### เขียน `ref_text` ให้ตรง

ข้อความต้องตรงกับเสียง **ทุกคำ รวมทั้งเครื่องหมายวรรคตอน** โมเดลใช้คู่
เสียง-ข้อความเรียนรู้ว่าผู้พูดออกเสียงหน่วยเสียงไหนอย่างไร — ถ้าข้อความผิด
มันจะเรียนรู้การจับคู่ที่ผิดไปด้วย

```yaml
voices:
  jarvis:
    ref_audio: voices/jarvis_ref.wav
    ref_text: "สวัสดีครับ ผมคือผู้ช่วยส่วนตัวของคุณ ยินดีที่ได้รับใช้"
    speed: 1.0
```

> **เคล็ดลับ:** ใช้ STT sidecar ถอดคลิปอ้างอิงเองเพื่อเป็นจุดตั้งต้น แล้ว
> ค่อยแก้ด้วยมือ — เร็วกว่าพิมพ์เองและมักตรงกว่าที่คิดไว้
>
> ```bash
> ffmpeg -i voices/jarvis_ref.wav -f s16le -ac 1 -ar 16000 - \
>   | curl -s -X POST localhost:8768/stt \
>       -H "X-Jarvis-Token: $JARVIS_STT_TOKEN" --data-binary @-
> ```

## การจูนคุณภาพกับความเร็ว

| พารามิเตอร์ | ช่วงที่ใช้ได้ | ผล |
|---|---|---|
| `step` | 16–48 | จำนวน flow-matching step — ต่ำ = เร็ว แต่เสียงหยาบและอาจสั่น ค่า 32 คือจุดสมดุล ต่ำกว่า 16 มักฟังไม่ไหว |
| `cfg` | 1.5–3.0 | ยิ่งสูงยิ่งเกาะเสียงอ้างอิง แต่สูงเกินไปเสียงจะแข็งและ over-articulate |
| `speed` | 0.8–1.3 | นอกช่วงนี้เริ่มได้ยินว่าเป็นการยืด/บีบเสียง |

### ถ้าอยากให้ตอบเร็วขึ้น

เรียงตามผลที่ได้ต่อความเสี่ยง:

1. **ลด `step` เป็น 24** — ลดเวลาราว 25% แทบไม่รู้สึกถึงคุณภาพที่ลดลง
2. **ทำให้คำตอบสั้นลง** — แก้ที่ `hermes.instructions` ไม่ใช่ที่โมเดลเสียง
   คำตอบ 2 ประโยคเร็วกว่าคำตอบ 5 ประโยคที่สังเคราะห์เร็วขึ้น 20%
3. **ลดความยาวคลิปอ้างอิง** — คลิป 8 วินาทีเร็วกว่าคลิป 15 วินาทีอย่างมี
   นัยสำคัญ เพราะเป็น context ของทุก request
4. **แบ่งประโยคให้ถี่ขึ้น** — ลด `max_chars` ใน `split_sentences` ทำให้
   เสียงแรกออกเร็วขึ้น แลกกับรอยต่อระหว่างประโยคที่ได้ยินชัดขึ้น

### วัดผล

ทุก response ของ `/tts` มี header บอกเวลา:

```bash
curl -sD- -o /dev/null -X POST http://msi-4:8769/tts \
  -H "X-Jarvis-Token: $JARVIS_TTS_TOKEN" -H 'Content-Type: application/json' \
  -d '{"text":"ทดสอบระบบเสียงภาษาไทย"}' | grep -i x-jarvis
```

เอา `X-Jarvis-Audio-Seconds ÷ X-Jarvis-Latency` = real-time factor
ถ้าได้ต่ำกว่า 1 แปลว่าสังเคราะห์ช้ากว่าเวลาพูดจริง ซึ่งจะรู้สึกได้ทันทีใน
บทสนทนา — ควรอยู่ที่ 2 ขึ้นไปบน GPU ที่เหมาะสม

## หลายเสียง

นิยามได้ไม่จำกัดใน `voices.yaml` แล้วเลือกตอน request:

```bash
curl -X POST http://msi-4:8769/tts \
  -H "Content-Type: application/json" \
  -d '{"text":"สวัสดีค่ะ","voice":"friday"}' --output friday.wav
```

ทุกเสียงใช้โมเดลเดียวกันใน VRAM — เพิ่มเสียงไม่ได้เพิ่มการใช้หน่วยความจำ
มีแต่คลิปอ้างอิงที่ถูกโหลดตอนใช้

## ข้อจำกัดที่ควรรู้

- **ไม่มี streaming ในตัว** โมเดลสร้างเสียงทั้งก้อนก่อนคืน การแบ่งประโยค
  คือวิธีที่ใกล้เคียง streaming ที่สุดที่ทำได้
- **ตัวเลขและภาษาอังกฤษปนไทย** ยังอ่านผิดได้ — บรรเทาโดยสั่งใน
  `hermes.instructions` ให้ agent เขียนตัวเลขเป็นคำอ่านตั้งแต่ต้นทาง
- **อารมณ์คุมไม่ได้** โทนเสียงมาจากคลิปอ้างอิงล้วน ๆ อยากได้โทนอื่นต้อง
  อัดคลิปใหม่ด้วยโทนนั้น

## เรื่องสิทธิ์

ใช้เฉพาะเสียงที่คุณมีสิทธิ์โคลน การโคลนเสียงบุคคลจริงโดยไม่ได้รับความยินยอม
ผิดกฎหมายในหลายประเทศ และไม่ใช่การใช้งานที่โปรเจกต์นี้สนับสนุน
