`http://…:8765/hud/` หน้าจะขึ้นได้แต่กดพูดไม่ได้ · cert เป็น self-signed

## Token

```bash
./scripts/new-hud-token.sh
```

สร้าง token ใหม่ เขียนลง `~/.hermes/.env` และ restart service ให้อัตโนมัติ

รูปแบบเป็น 3 กลุ่ม กลุ่มละ 5 ตัว เช่น `rnu37-6vx6w-4vv9d` ใช้ชุดตัวอักษรที่
**ตัด `0 O 1 l I` ออก** เพราะต้องพิมพ์บนคีย์บอร์ดมือถือ

**ทำไมไม่ใช้ token ยาว ๆ:** HUD เข้าถึงได้เฉพาะ LAN หรือ tailnet และการเดาแต่ละ
ครั้งต้องเปิด WebSocket handshake เต็มรูปแบบ — brute force ไม่ใช่ภัยที่แท้จริง
ส่วน token ที่ยาวจนอ่านไม่ไหวจะถูกก็อปวางในแชทแทนที่จะพิมพ์ ซึ่งเสี่ยงกว่า

> ใครถือ token นี้สั่ง agent ที่มีสิทธิ์รันคำสั่งบนเครื่องได้ — ปฏิบัติกับมัน
> เหมือนรหัสผ่าน และหมุนทันทีเมื่อหลุด

## Origin allowlist — ด่านที่คนติดกันมากที่สุด

WebSocket ของ HUD ต้องผ่าน **สองด่าน**: Origin host ต้องอยู่ใน allowlist
**และ** token ต้องถูก · ค่าเริ่มต้นมีแค่ `jarvis.local`, `jarvis`, `localhost`,
`127.0.0.1` — **เปิดด้วย LAN IP จะถูกปฏิเสธเสมอแม้ token ถูก**

```yaml
# server.yaml
security:
  extra_origin_hosts: ["192.168.139.181", "hermesjarvis.orb.local"]
```

อาการเมื่อลืม: มุมบนขึ้น `LINK DOWN`, Socket `offline`, ต่อใหม่ทุก 3 วินาที
โดยไม่มี error ให้เห็น

> `curl` จะ **ไม่มีวันเจอบั๊กนี้** เพราะไม่ส่ง `Origin` header ซึ่งโค้ดตีความว่า
> เป็น native client แล้วปล่อยผ่าน — ต้องทดสอบด้วยเบราว์เซอร์จริงเท่านั้น

## กล้อง — ให้มันดูของจริง

### ตรวจก่อนสร้าง

| คำถาม | คำตอบที่ยิงทดสอบจริง |
|---|---|
| โมเดลอ่านภาพได้ไหม | **ได้** — ส่งภาพตรงไปที่ `vllm-spark-01/gemma4-26b-uncensored` แล้วมันบรรยายกลับมา |
| Hermes รับภาพไหม | **รับ** — `image_url` / `input_image` รวม data URL · ของอื่นปฏิเสธพร้อมบอกชื่อ error |
| ขนาดสูงสุด | 10 MB ต่อ request · JPEG กว้าง 1280 อยู่ราว 60–300 KB |

งานที่เหลือจึงเป็นแค่การต่อท่อ ไม่ต้องรอเปลี่ยนโมเดล

### ใช้ยังไง

พิมพ์ `เปิดกล้อง` / `อ่านเอกสาร` หรือกดไทล์ **กล้อง** · แสดงใน**แผงเดียวกับแผนที่** ปิดด้วย
**✕** หรือ **Esc** — และการปิดจะ**หยุด track จริง** ไม่ใช่แค่ซ่อนภาพ (ไฟกล้องต้องดับ)

ในแผงมีปุ่ม **ถ่ายแล้วให้อ่าน** · **สลับกล้อง** · และช่องพิมพ์คำถามเกี่ยวกับภาพ

> ⚠️ ต้องเปิดผ่าน **https (พอร์ต 8766)** เหมือนเรื่องตำแหน่ง — เบราว์เซอร์ไม่ให้เปิดกล้องบน http ธรรมดา

### ทำไมมันต่อกับแผนที่ได้เอง

`/api/look` ใส่ภาพลงใน **session เดียวกับที่คุยด้วยเสียง** ไม่ใช่ช่องทางแยก
บทสนทนาจึงต่อเนื่อง และเอเจนต์ยังมีเครื่องมือเดิมครบ

ทดสอบจริงตามโจทย์:

```
[ภาพโบรชัวร์] "นี่ที่ไหนครับ"
  → "ที่นี่คือ ฟาร์มจระเข้ และสวนสัตว์สมุทรปราการ ครับ
     โดยในภาพจะมีรายละเอียดบอกเวลาโชว์จับจระเข้คือช่วงเก้าโมงเช้าถึงห้าโมงเย็นครับ"

"เปิดแผนที่ที่ที่นั่นให้ดูหน่อยครับ"
  → เรียก terminal → POST /api/map → แผงขึ้นชื่อ "ฟาร์มจระเข้และสวนสัตว์สมุทรปราการ"
```

อ่านทั้ง**ชื่อและเวลาโชว์**ออกจากภาพ แล้วส่งต่อให้แผนที่เองโดยไม่ต้องต่อสายเพิ่ม

## แผนที่ — Google Maps / Earth

### สิ่งที่ค้นแล้วพบ (และมันเปลี่ยนวิธีออกแบบ)

**`earth.google.com` ฝังใน iframe ไม่ได้** — ตอบกลับมาด้วย
`x-frame-options: SAMEORIGIN` (ยิงเช็กกับของจริงแล้ว) ดังนั้น iframe ที่ชี้ไปหามัน
จะว่างเปล่า ไม่ว่าจะจัดวางยังไงก็ตาม

หน้าที่ลิงก์มา (`developers.google.com/maps/documentation/earth`) เป็น**คู่มือผู้ใช้**
ของ Google Earth — เรื่อง project, KML, Street View — **ไม่ใช่ API สำหรับฝัง**

ทางที่ใช้ได้จริงมีสองทาง:

| | ใช้ทำอะไร | ต้องมี |
|---|---|---|
| **Maps Embed API** `/maps/embed/v1/*` | ฝัง iframe ได้ (ตรวจแล้วว่าไม่ส่ง X-Frame-Options) · `maptype=satellite` คือภาพดาวเทียมชุดเดียวกับที่คนเรียกว่า Google Earth | API key |
| **Maps JavaScript API — `maps3d`** | โลก 3 มิติเอียงได้จริง ผ่าน `<gmp-map-3d>` ในหน้าที่เราเสิร์ฟเอง (`hud/earth3d.html`) | API key + Map Tiles API + ผูกบัญชีเรียกเก็บเงิน |

### ตั้งค่า

```bash
# ~/.hermes/.env
JARVIS_MAPS_API_KEY=AIza...
```

สร้างคีย์ที่ console.cloud.google.com → เปิด **Maps Embed API** (และ **Map Tiles
API** ถ้าจะใช้ 3 มิติ) → จำกัดคีย์ด้วย HTTP referrer ของ host นี้ · แล้ว
`systemctl --user restart jarvis-voice`

> ยังไม่ใส่คีย์ก็ใช้งานได้ — แผงจะขึ้นมาพร้อมข้อความบอกว่าต้องทำอะไร ไม่ใช่ iframe ว่าง

### เรียกใช้

```bash
curl -s -X POST http://127.0.0.1:8765/api/map \
  -H 'Content-Type: application/json' \
  -d '{"q":"อนุสาวรีย์ชัยสมรภูมิ","mode":"satellite"}'
```

| mode | ผล |
|---|---|
| `satellite` | ภาพดาวเทียม (ค่าเริ่มต้น) |
| `roadmap` | แผนที่ถนน |
| `earth` | โลก 3 มิติ หมุนช้า ๆ |
| `streetview` | สตรีทวิว |
| `directions` | เส้นทาง (ต้องมี `origin` และ `destination`) |
| `{"action":"dismiss"}` | ปิดแผง |

ในหน้า HUD พิมพ์ `แผนที่ <ที่ไหน>` ก็ได้ — เป็นทางลัดข้ามเอเจนต์ไปเลย ·
`ทางไป <ที่ไหน>` จะขอตำแหน่งของคุณก่อนแล้วลากเส้นทางให้

### "จากที่ผมอยู่ไป..."

`origin: "here"` (หรือพูดว่า *ที่ผมอยู่* / *ตำแหน่งปัจจุบัน*) ใช้ได้ แต่ต้องเข้าใจว่า
**เซิร์ฟเวอร์ไม่รู้ว่าคุณอยู่ไหน และเอเจนต์ก็ไม่รู้** — มีแต่เบราว์เซอร์ที่รู้
และรู้ได้ต่อเมื่อคุณกดอนุญาต

```
HUD ──กดอนุญาต──> navigator.geolocation ──POST /api/here──> เซิร์ฟเวอร์จำไว้ในแรม
                                                                      │
เอเจนต์ ──{"origin":"here"}──> /api/map ───────────────────────────────┘
```

> ⚠️ **ต้องเปิด HUD ผ่าน https (พอร์ต 8766)** — เบราว์เซอร์ไม่ยอมให้ขอตำแหน่งบน
> http ธรรมดา ไม่ว่าจะเป็น LAN หรือไม่ · เปิดผ่าน `:8765` จะขึ้นข้อความบอกตรง ๆ
> ไม่ใช่เงียบหาย

ตำแหน่งถูกขอ**ตอนที่คุณสั่งหาเส้นทาง** ไม่ใช่ตอนเปิดหน้า — กล่องขออนุญาตที่เด้งมา
โดยไม่มีเหตุผล คนกดปฏิเสธโดยอัตโนมัติ

**เก็บในแรมอย่างเดียว** อายุ 15 นาที (`JARVIS_HERE_TTL`) ไม่เขียนลงดิสก์ ไม่อยู่ข้ามการ
restart · มันคือตำแหน่งคนหนึ่งคนในบ้านหนึ่งหลัง ไม่ใช่ประวัติการเดินทาง ·
`POST /api/here` ต้องมี token (มีแต่ HUD ที่ตั้งได้ ไม่ใช่โปรเซสไหนก็ได้ในเครื่อง)

### ข้อจำกัดที่เจอจากการทดสอบจริง

| อาการ | สาเหตุ |
|---|---|
| Street View ส่งชื่อสถานที่ไปแล้ว `Invalid 'location' parameter` | Street View รับ**พิกัดหรือ pano id เท่านั้น** · แปลงชื่อ→พิกัดคือ Geocoding API ซึ่งต้องผูกบัตร → ส่งชื่อมาจะตกไปใช้ดาวเทียมแทน และหัวข้อบอกว่าทำไม |
| 3 มิติขึ้นสี่เหลี่ยมดำ | Map Tiles API ต้องผูกบัญชีเรียกเก็บเงิน · `earth` เลยหมายถึงดาวเทียมซูม 18 เป็นค่าเริ่มต้น เปิดของจริงด้วย `JARVIS_MAPS_3D=1` |
| iframe ขาวอยู่นาน | ปกติ · Google ใช้เวลา 10–15 วินาทีกว่าจะวาดเสร็จ ไม่ใช่ error |

**ปุ่ม ✕ มุมขวา** (หรือ Esc) ปิดแผนที่แล้วกลับไปที่บทสนทนา — บทสนทนาไม่หายไปไหน
มันแค่ถูกซ่อนไว้

### ทำไม `/api/map` ไม่ต้องใช้ token เมื่อเรียกจาก localhost

เอเจนต์รันอยู่บนเครื่องเดียวกันและเรียกผ่าน terminal tool · ถ้าบังคับให้ส่ง token
ก็ต้องเอา token ไปใส่ใน prompt ซึ่งจะไปโผล่ใน log และ transcript

**ปลอดภัยเพราะการออกแบบ ไม่ใช่เพราะความไว้ใจ** — `/api/map` **ไม่รับ URL** มันรับแค่
ชื่อสถานที่ แล้วประกอบ URL จากเทมเพลตของเราเอง สิ่งที่แย่ที่สุดที่โปรเซสในเครื่อง
จะทำได้คือแสดงสถานที่ผิด · คีย์อยู่ฝั่งเซิร์ฟเวอร์ เอเจนต์ไม่เคยเห็น

## API (ต้องมี auth)

HTTP API รับ token จาก **cookie หรือ header `X-Jarvis-Token`** เท่านั้น —
**ไม่รับ `?token=`** (ต่างจาก WebSocket ที่รับทั้งสองแบบ)

```bash
# แบบนี้ได้
curl -sk -H "X-Jarvis-Token: $TOKEN" https://host:8766/api/loadout
curl -sk --cookie "jarvis_token=$TOKEN" https://host:8766/api/loadout

# แบบนี้ได้ 401
curl -sk "https://host:8766/api/loadout?token=$TOKEN"
```

| Endpoint | คืนอะไร |
|---|---|
| `/api/loadout` | brain / STT / TTS ที่ทำงานจริง |
| `/api/machines` | สถิติเครื่อง host + GPU node |
| `/api/usage` | token ที่ใช้วันนี้ จำนวนเทิร์น |
| `/api/warm` | พรีฟิกซ์ของโมเดลอุ่นอยู่ไหม อายุเท่าไหร่ |
| `/api/ack` | คลิปคำรับทราบ (PCM) |
| `/api/here` | `POST` บอกตำแหน่งผู้ใช้ · `GET` ถามว่ารู้ไหม |
| `/api/look` | `POST` ภาพหนึ่งเฟรม → คำตอบจากเอเจนต์ |
| `/ws` | WebSocket ของเสียงและ event ทั้งหมด |

**สองอันนี้ไม่ต้องใช้ token เมื่อเรียกจาก localhost** เพื่อให้เอเจนต์เรียกเองได้
โดยไม่ต้องเอา token ไปใส่ใน prompt:

| Endpoint | รับอะไร |
|---|---|
| `/api/map` | ชื่อสถานที่ + โหมด — **ไม่รับ URL** ประกอบเองจากเทมเพลต |
| `/api/camera` | `facing` หน้า/หลัง เท่านั้น — ไม่รับเนื้อหาใด ๆ |

ปลอดภัยเพราะการออกแบบ ไม่ใช่เพราะความไว้ใจ: สิ่งที่แย่ที่สุดที่โปรเซสในเครื่องทำได้
คือเปิดแผนที่ผิดที่ หรือเปิดกล้อง (ซึ่งยังต้องให้ผู้ใช้กดถ่ายอยู่ดี)

## VIEWS — Kanban / Hermes Dashboard

ปุ่มในแผง VIEWS เปิดหน้าเว็บของ Hermes ใน viewer ที่ซ้อนอยู่บน HUD

หน้าเหล่านี้ไม่ได้เสิร์ฟจาก voice server แต่มาจาก **dashboard ของ Hermes เอง**
ที่ผูกกับ `127.0.0.1:9119` แล้วให้ voice server ทำ TLS reverse proxy ที่ 9443:

```
เบราว์เซอร์ ──https :9443──▶ voice server (ตรวจ token) ──http :9119──▶ hermes dashboard
```

ที่ต้องมี proxy คั่นเพราะ dashboard ผูกกับ loopback อย่างเดียว และหน้า HUD เป็น
https จะ iframe หน้า http ไม่ได้ · proxy จึงทำสองอย่าง: ใส่ TLS และบังคับ auth

### เปิดใช้งาน

```bash
systemctl --user enable --now hermes-dashboard
```

ครั้งแรกต้อง build web UI ก่อน (ต้องมี npm):

```bash
hermes dashboard --port 9119 --host 127.0.0.1 --no-open   # build แล้ว Ctrl-C
```

> ใช้ `hermes serve` ไม่ได้ — เป็นโหมด headless ที่ปิด web UI ไว้ และจะตอบ
> `{"error":"Headless backend (hermes serve): web UI disabled"}` ต้องใช้
> `hermes dashboard` เท่านั้น

### ถ้ากดแล้วหน้าว่าง

เบราว์เซอร์จำ cert exception **แยกตามพอร์ต** · คุณกด Proceed ให้ `:8766` ไปแล้ว
แต่ `:9443` เป็นคนละ origin จึงยังไม่ได้รับอนุญาต และ iframe จะล้มแบบเงียบ ๆ

เปิด `https://<host>:9443/` ตรง ๆ หนึ่งครั้ง กด Advanced → Proceed แล้วกลับมา
ที่ HUD — ปุ่มจะทำงาน

> cookie ไม่ใช่ปัญหา: cookie ไม่แยกตามพอร์ต ตัวที่ตั้งไว้ตอนเข้า `:8766`
> ถูกส่งไป `:9443` ให้เองอยู่แล้ว

## โหมดคุยต่อเนื่อง (hands-free)

กด **ENGAGE VOICE** ครั้งเดียว แล้วพูดได้เรื่อย ๆ — ไมค์เปิดค้าง ระบบตรวจเองว่า
เทิร์นเริ่มและจบตรงไหน · หยุดพูดไปเฉย ๆ โหมดยังเปิดอยู่ ต้องกด **END SESSION**
ถึงจะปิด

**ใช้ได้ทั้งสองโหมดพร้อมกัน:**

| ปุ่ม | ทำอะไร |
|---|---|
| ENGAGE VOICE (ปุ่มใหญ่) | เปิด/ปิด session คุยต่อเนื่อง |
| วงแหวน หรือ Space | กดพูดทีละครั้งแบบเดิม |

ทั้งสองใช้ตัวจับเสียงร่วมกัน จึงมี guard ไม่ให้ทำงานพร้อมกัน

### ตัวตรวจจับทำงานยังไง

รันบนมิเตอร์ระดับเสียงที่ worklet คำนวณอยู่แล้ว — ตัวเลขเดียวต่อเฟรม 80 ms
ไม่ได้เพิ่มอะไรในเส้นทางเสียง

```
[รอฟัง] ──เจอเสียงพูด 160ms──▶ [กำลังฟัง] ──เงียบ 650ms──▶ ส่งให้ agent
   ▲                                                            │
   └──────────── cooldown 1.2 วิ ◀───────────────────────────────┘
```

**สี่อย่างที่ทำให้ใช้ได้ในห้องจริง ไม่ใช่แค่บนโต๊ะเงียบ ๆ:**

1. **เกณฑ์วิ่งตามห้อง** — ค่าคงที่ใช้ได้ห้องเดียว · ระบบวัด noise floor ตลอดเวลา
   แล้วใช้เกณฑ์เป็นกี่เท่าของมัน · **หยุดวัดตอนมีใครพูด** ไม่งั้น floor ไต่ตาม
   เสียงคนพูดจนหูหนวก · ขึ้นช้า ลงเร็ว
2. **เทียบกับเสียงดังที่สุดของเทิร์นด้วย** — browser auto gain control ดันเสียง
   เงียบให้ดังขึ้น เกณฑ์แบบสัมบูรณ์จึงไม่มีวันเห็นความเงียบ (เคยทำให้เทิร์นไม่จบเลย)
3. **pre-roll 1.2 วินาที** — เก็บเสียงก่อนตัวตรวจจับตื่นไว้เสมอ แล้วส่งไปด้วย ·
   ถ้าไม่มี **พยางค์แรกจะหายทุกครั้ง** เพราะตัวตรวจจับต้องรอให้แน่ใจก่อนถึงจะเปิดเทิร์น
4. **นับเป็นเสียงพูด ไม่ใช่เวลาที่ผ่านไป** — เทิร์นที่เปิดเพราะเสียงประตูจะรอครบ
   หน้าต่างจบเทิร์นเหมือนกัน · ถ้าวัดด้วยเวลาจะผ่านตัวกรอง แล้ว**ตอบรับห้องว่าง**

### ตอบรับทันที

พอพูดจบ ระบบเล่นเสียงตอบรับสั้น ๆ ("ครับ" / "อืม") ภายในเสี้ยววินาที แล้วค่อยตอบจริง
· ไม่ได้เร็วขึ้นเลย แต่เปลี่ยนความรู้สึกทั้งหมด — คนเราพอพูดจบแล้วเงียบสนิท 6-14
วินาทีจะคิดว่าอีกฝ่ายไม่ได้ยิน

คลิปสังเคราะห์ครั้งเดียวที่ `/api/ack` แล้ว HUD โหลดเก็บไว้ตอนเปิด session ·
เล่นจริงใช้ **12 มิลลิวินาที**

> `ack_after_seconds` ที่ upstream มีใน config **ไม่ได้ถูกอ่านเลย** (grep ได้ 0)
> ส่วนนี้เขียนขึ้นใหม่ทั้งหมด

### การขัดจังหวะ

พูดแทรกตอนบอทกำลังพูดได้ — แต่ต้องดังกว่าเสียงห้อง **6 เท่า** และนานเกิน **420ms**

เกณฑ์เข้มนี้ใช้**ตลอดเวลาที่ agent ทำงาน** ไม่ใช่แค่ตอนมีเสียงออกลำโพง · เคยผูกไว้
กับเสียงอย่างเดียวแล้วพัง: ช่วง 5 วินาทีที่ agent คิด เสียงห้องธรรมดาเปิดเทิร์นใหม่ได้
และ**การเปิดเทิร์นใหม่คือการยกเลิกงานที่ส่งไปแล้ว** — คำตอบจึงไม่มีวันมาถึง

> ขัดจังหวะยากหน่อย เป็นปัญหาที่เล็กกว่าไม่ได้คำตอบเลยมาก

### ปรับจูนเอง

ไม่ต้อง deploy ใหม่ — เปิด Console:

```javascript
localStorage.setItem("jarvisVad", JSON.stringify({endMs: 1200}))
localStorage.setItem("jarvisVadDebug", "1")   // ดูค่าสด ๆ ในแถว Hands-free
```

| ค่า | เริ่มต้น | ปรับเมื่อ |
|---|---|---|
| `endMs` | 650 | ตัดบทเร็วไปตอนหยุดคิด → 1000-1500 |
| `prerollMs` | 1200 | คำแรกยังหาย → 2000 |
| `startMs` | 160 | ตอบสนองช้า → 120 |
| `speakMargin` | 3.0 | ห้องมีเสียงรบกวน เด้งเอง → 4-5 |
| `bargeMargin` | 6.0 | บอทตัดตัวเอง → 8-10 · **อย่าต่ำกว่า 4** |
| `cooldownMs` | 1200 | — |

`jarvisVadDebug` แสดง `0.312>0.085 sil240 busy` = ความดัง > เกณฑ์ · เงียบมากี่ ms ·
agent ทำงานอยู่ไหม · และ log จำนวนเฟรม pre-roll ที่ส่งไปทุกเทิร์น
